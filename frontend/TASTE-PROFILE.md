# MyBikeLab taste profile

Consolidated record of the visual criteria that should guide future MyBikeLab
work. It keeps the durable conclusions from the design reviews without
depending on discarded prototype files.

## Core equation

1. **Premium restraint, zero costume.** The interface must feel considered and
   precise without pretending to be a newspaper, workshop manual or control
   room.
2. **Structured surfaces.** Panels need visible separation and moderate relief.
   Flat utility sheets and white-on-white layouts do not create enough
   hierarchy.
3. **Moderate density.** Put the overview and key decisions first. Preserve
   breathing room around dense blocks without hiding useful information below a
   long scroll.
4. **Wide-screen balance.** Use available width and avoid both a narrow,
   linear column and a crowded dashboard.
5. **Punctual accents.** Accent color should identify action, focus or meaning,
   not decorate every surface.
6. **Useful visuals only.** An illustration must communicate component data or
   structure immediately. Otherwise it should be omitted.

## Keep

- Real product surfaces and real information. Every label must earn its place.
- Clear stat ledgers and aligned numeric figures.
- Informative component schematics when they help explain the product.
- The comparator as an overview-first surface with filters, active selections
  and a dense comparison table.
- A single component and layout system translated across supported themes.

## Avoid

- Decorative counters, tickers, stamps, fake technical labels and editorial
  role-play.
- Oversized display type competing with useful content.
- Near-black dark surfaces, flat white-on-white layouts and mass red accents.
- Stock photography or photography-dependent composition for the product MVP.
- Decorative gradients, noise, glows or pseudo-information.
- Structural background bands when panel hierarchy is sufficient.

## Layout and interaction

- Prefer balanced, centered-friendly compositions at wide sizes.
- Preserve a clear relationship between sections, controls and results at every
  responsive breakpoint.
- Keep interaction states visible and semantic. Do not hide behavior merely to
  simplify a visual reference.
- Treat responsive changes as the same visual logic adapted to the available
  space, not as unrelated layouts.

## Type, data and color

- Use typography, spacing and data presentation to create distinction rather
  than stylistic costume.
- Give measured values a consistent, highly legible numeric treatment.
- Prefer a cool, restrained light presentation.
- Dark mode may exist as a moderate charcoal translation of the same system.
- A warm alternate presentation is acceptable only when restrained and clearly
  subordinate to the product information.

## Decision filter

Before retaining a visual element, ask:

1. Does it communicate product information, hierarchy or interaction?
2. Does it improve overview and comprehension at the target viewport?
3. Does it remain coherent across themes and responsive states?
4. Would removing it make the product less understandable?

If the answers are negative, remove the element. If the intended result is
ambiguous, stop and ask before inventing a treatment.
