## TASK-003 — ContactForm inline validation + success icon radius fix

**Files changed:**
- `frontend/src/components/ContactForm.jsx`
- `frontend/tailwind.config.js` *(deviation — see below)*

Changes to `ContactForm.jsx`:
- Added `errors` state: `useState({ name: '', email: '', message: '' })`
- Replaced `onSubmit` handler: validates all three required fields with `.trim()`, calls `setErrors`, returns early if any error is present; existing `mailto:` flow and `setSent(true)` are unchanged.
- Removed `required` attribute from `name`, `email`, and `message` inputs.
- Added `<p className="mt-1 t-body-sm text-signal-down">` error element inside each of the three field wrappers, conditionally rendered when the error string is non-empty.
- Changed `rounded-full` to `rounded-none` on the success-state icon container.

### Design decisions
`onChange` handlers are untouched — errors appear on submit only, never on blur or change. The `errors` state shape matches the spec exactly; `company` is excluded.

### Deviations
**`tailwind.config.js` was modified.** The `signal` color group (`up`, `down`, `warn`, `info`) was entirely absent from the Tailwind config. Without it, `text-signal-down` is not generated by Tailwind and would be a no-op at runtime. The task flagged this risk and the fix was applied as a prerequisite. The full `signal` palette was registered (not just `down`) to keep the config consistent with `design-tokens.css`.

**Review recommended:** if the design system intentionally restricts `signal-up`, `signal-warn`, and `signal-info` to specific contexts, adding the full group should be confirmed or narrowed.

### Tradeoffs
- Errors persist until the next submit attempt, then reset for all fields and recomputed — fields that now pass clear, fields that still fail stay visible. This matches FR-006 and UC-005.
- `type="email"` without `required` still triggers browser-native format validation on some browsers. This is pre-existing behaviour; the task only requires emptiness validation.

### Open questions
- Should `email` also validate format (non-empty but syntactically invalid)? Currently a non-empty invalid email passes custom validation and reaches the `mailto:` handler.
- Confirm whether adding the full `signal` palette to `tailwind.config.js` is acceptable, or whether only `signal-down` should be registered.

### Bug fixes
**`text-signal-down` was non-functional.** The `signal` color group was missing from `tailwind.config.js`, so the class was never generated by Tailwind. The config has been corrected.
