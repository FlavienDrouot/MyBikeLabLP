# Code Review — MyBikeLab (projet entier)

**Date:** 2026-06-03 22:10
**Scope:** `frontend/src/` — registry (`wheelProperties.jsx`), store (slices + selectors), couche data (`wheelUtils`, `wheelValidator`, `wheelsData_*`), composants MiniComparator (table, filtres, panneau détail, carousel, mesure), `ContactForm`. Lint + 206 tests vérifiés.
**Verdict:** 🟡 minor adjustments

## Summary
Architecture solide et cohérente : le « registry-driven » de `wheelProperties.jsx` tient ses promesses — ajouter une propriété se fait réellement à un seul endroit, et tout (filtres, tri, colonnes, options) en découle par itération. Lint propre, 206/206 tests verts, immutabilité Redux respectée, sélecteurs mémoïsés corrects. Aucun blocker. Les points à traiter sont : un token Tailwind invalide qui passe inaperçu (cosmétique mais répété), un tri numérique qui mal classe les valeurs `null`, un gros bloc de code mort, et une divergence d'entêtes dans la table de mesure.

## Findings

### 🟠 Important

**Token Tailwind `text-ink-500` inexistant — couleur jamais appliquée**
- 📍 `config/wheelProperties.jsx:113`, `:397`, `:487` ; `components/MiniComparator/FilterPanel.jsx:331`
- **Problem:** L'échelle `ink` définie dans `tailwind.config.js:17-30` ne contient que `1`…`12`. La classe `text-ink-500` ne génère donc aucune règle CSS. Les sous-libellés de marque (colonnes Model, Hub, Spokes) et le message « no results » héritent de la couleur du parent au lieu du gris atténué visé (vraisemblablement `ink-7`).
- **Impact:** Hiérarchie visuelle perdue : le nom de marque s'affiche dans la même couleur que le modèle au lieu d'être discret. Bug silencieux (ni lint ni test ne le détectent).
- **Fix:** Remplacer `text-ink-500` par le token voulu, p. ex. `text-ink-7` (cohérent avec les autres sous-libellés meta du projet).

### 🟡 Suggestions

**Tri numérique : les valeurs `null` sont classées comme 0**
- 📍 `store/selectors/wheelsSelectors.js:60-66`
- **Problem:** `va - vb` avec `va = null` (prix sans valeur via `minPrice`, ou `weight` absent) coerce `null → 0`. Une roue sans prix connu remonte donc en tête d'un tri prix croissant (« moins chère »), et en tête d'un tri poids croissant (« plus légère »).
- **Fix:** Pousser les `null`/`NaN` en fin de liste quel que soit le sens, p. ex. traiter `va == null` comme `+Infinity` avant la soustraction.

**Bloc de données mort (~295 lignes commentées)**
- 📍 `data/wheelsData.js:13-308`
- **Problem:** L'ancien jeu de données placeholder est conservé en commentaire (et référence `wheelPlaceholderUrl`, qui n'est même plus importé dans ce fichier). Le commentaire lui-même indique « remove once all brands are scraped » — les 4 marques sont désormais ingérées.
- **Fix:** Supprimer le bloc (l'historique git le conserve si besoin). Préférer la suppression à la mise en commentaire.

**`MeasuringTable` : entêtes divergents de la table visible**
- 📍 `components/MiniComparator/MeasuringTable.jsx:65` vs `components/MiniComparator/ComparisonTable.jsx:165-171`
- **Problem:** Le commentaire en tête du fichier affirme « same content + same classes => measured widths equal ». En pratique l'entête mesuré utilise `text-xs font-medium`, alors que l'entête visible utilise `text-[10px] font-semibold` et ajoute une flèche `↓` (`ml-1`) sur la colonne triée — non présente dans la table de mesure. Le `th` trié peut donc être plus large que la largeur figée mesurée et rogner son contenu.
- **Fix:** Aligner les classes d'entête de `MeasuringTable` sur celles de la table visible, ou (plus sûr) réserver la largeur de la flèche de tri dans la mesure. A minima, corriger le commentaire qui sur-affirme l'équivalence.

### ⚪ Nits
- `store/selectors/wheelsSelectors.js:9-11` : le ré-export de `minPrice` est justifié par « future tests / third-party imports » purement spéculatifs — à retirer si aucun consommateur réel.
- `components/MiniComparator/columnCells.jsx:5-9` : le fallback `safeT` est introduit « pour les legacy callers (TASK-005) » ; vérifier si TASK-005 est clos et si tous les appelants passent désormais `t`, auquel cas le fallback peut disparaître.
- `WheelImageCarousel.jsx:3` : `prefersReducedMotion` est évalué une seule fois au chargement du module ; il ne réagira pas à un changement de préférence en cours de session (acceptable, mais à noter).

## Open questions

- `discStandard` apparaît sous la forme `'Center Lock'` dans les données Zipp alors que `axle`/freehub utilisent d'autres casses — y a-t-il une convention de casse/valeurs canoniques attendue côté data pour éviter des doublons d'options de filtre (ex. `Center Lock` vs `centerlock`) ?
